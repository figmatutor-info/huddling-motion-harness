# /make-video $ARGUMENTS

`$ARGUMENTS` = `<영상이름>`(영문 소문자 · 숫자 · `-`). 레퍼런스는 `references/` 안의 이미지와 페이지 글만 쓴다.
너(메인)는 **순서를 돌리고 사람과 말하는 역할만** 한다. 만들기 · 판정은 에이전트에게 맡기고, 에이전트끼리는 `out/<영상이름>/_plan/` 파일로만 주고받는다. `CLAUDE.md`의 꼭 지킬 것 3개가 이 순서보다 우선한다.

## 시작
1. 준비물(`docs/` design · video · motion, `src/` screens · parts · patterns, `references/README.md`, `brief/BRIEF.template.md`)이 있는지 본다. 없으면 멈추고 알린다.
2. `out/<영상이름>/_plan/`을 만들고 `decisions.md`를 연다 (제목: 브리프 답 · 승인 · 수정 요청 · 질문 · 기본값으로 정한 것). 이미 있으면 `gates.md`와 `decisions.md`를 읽고 멈춘 단계부터 잇는다.
3. **`out/<영상이름>/BRIEF.md`가 없으면** 단계 0 브리프부터 한다 (새 영상이면 항상). 있으면 단계 1로.

## 게이트 돌리기 (모든 단계 공통)
```
에이전트가 만듦 → critic 판정 (gates.md)
  통과 → 사람에게 보여줌
  1번째 탈락 → "고칠 사람"에게 떨어진 조건만 넘겨 다시 → critic 다시
  2번째 탈락 ("멈춤: 사람에게 묻기") → 멈추고 사람에게 묻는다
```
- **critic을 통과하지 않은 것은 사람에게 보여주지 않는다.**
- 2번째 탈락 질문: 떨어진 조건 · 센 값 · 기준 · 고를 수 있는 길 2–3개 (첫째가 기본값).
- 사람에게 하는 질문은 영상 하나에 **3개 이하**. 할 때마다 `decisions.md` "질문"에 적는다. 승인 요청과 단계 0 브리프 세 질문은 세지 않는다.
- 에이전트의 "질문 후보"는 막히는 것만 묻고, 나머지는 기본값으로 정해 `decisions.md`에 적는다. 사람에게는 **"기본값으로 정한 것"을 5개 이내로만** 보여준다 (더 있으면 중요한 5개 + "나머지는 decisions.md").

## 순서
| 단계 | 누가 | 결과 (`_plan/`) | 게이트 | 사람 |
|---|---|---|---|---|
| 0 브리프 (`out/<영상이름>/BRIEF.md` 없을 때) | 메인이 묻고 director가 씀 | `brief/BRIEF.md` → `out/<영상이름>/BRIEF.md` | 브리프 | **브리프 승인** |
| 1 레퍼런스 | art-director | `references.md` | 레퍼런스 | 보여주기만 |
| 2 장면표 | director | `scenes.md` | 장면표 | **승인 ①** |
| 3 스냅보드 | builder | `snapboard/sNN.png` · `snapboard/all.png` · `review.md` | 스냅보드 | **승인 ②** |
| 4 생성 | builder | `out/<영상이름>/` · `review.md` | 생성 | — |
| 5 검수 · 렌더 | builder → critic | `render/<영상이름>.mp4` | 렌더 | 영상 + 판정 보여주기 |
| 6 규칙 제안 | critic | `gates.md` "규칙 제안" | — | 고른 것만 반영 |

- 단계 0: 세 가지만 한 번에 묻는다 — **분위기 · 핵심 메시지 · 엔드 카드 문구**. 질문마다 **기본값 = 지난 브리프의 답**(지금 `brief/BRIEF.md`에 적힌 값, 없으면 기본값 없이)을 같이 보여준다. 다른 것은 묻지 않는다. 답을 `decisions.md` "브리프 답"에 적고 director에게 초안을 맡긴다 (`brief/BRIEF.md`를 덮어씀). critic 통과 뒤 초안을 보여주고, 승인되면 `decisions.md`에 `승인 브리프 <날짜>`를 적고 **`brief/BRIEF.md`를 `out/<영상이름>/BRIEF.md`로 복사**한 뒤 단계 1로. 이후 단계는 이 복사본을 읽는다.
- 단계 3은 승인 ①이, 단계 4는 승인 ① · ② 둘 다 `decisions.md`에 있어야 시작한다. 승인 전에는 `_plan/` 밖에 아무것도 만들지 않는다.
- 승인은 사람이 분명히 승인했을 때만 `decisions.md`에 `승인 ① 장면표 <날짜>`처럼 적는다.
- 사람이 고치라고 하면 `decisions.md`에 "수정 요청: …"으로 적고 그 단계 주인 에이전트부터 다시 돈다 (게이트도 다시). 수정 요청은 탈락 횟수로 세지 않는다.

## 보여주기 (게이트 통과 뒤)
짧게, 초보자도 고를 수 있게:
- 브리프: `brief/BRIEF.md` 메시지 순서를 장면마다 한 줄(문구 · 화면 파일) → "승인할까요, 고칠 곳이 있나요?"
- 레퍼런스: 가져올 것 / 가져오지 않을 것 요약 5줄 이내
- 장면표: 장면마다 한 줄(초 · 종류 · 문구 · Pattern) + 길이 · 계획상 움직이는 프레임 % + 기본값으로 정한 것(5개 이내) → "승인할까요, 고칠 곳이 있나요?"
- 스냅보드: 모아보기 `snapboard/all.png` 경로 먼저 + 장면마다 대표 프레임 PNG 경로 + 판정 요약 → 같은 질문. 고친 장면만 다시 보여줄 때도 모아보기는 새로 만든 것을 준다
- 렌더: 영상 경로 · 길이 · 움직이는 프레임 전체 % · 장면별 % · 계획 비율과 비교 · 판정 표

## 6 규칙 제안
`gates.md` "규칙 제안"의 후보를 번호 목록으로 보여주고 고르게 한다. **고른 것만** 적힌 곳(`CLAUDE.md` · `docs/…` · 에이전트 파일)에 넣고, 넣은 곳을 한 줄씩 알린다. `docs/`와 `src/`는 사람이 고른 경우에만 고친다.
